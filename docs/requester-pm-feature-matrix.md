# Pat 功能矩阵

> 基于当前 `app/requester`、`app/pm`、`features/requester`、`features/pm` 及 Supabase 迁移梳理。Requester 与 PM 按各自实际业务链路分别列出，不将两端不共享的功能混合对照。
>
> 状态说明：**已实现** = 已有可访问页面及对应业务动作；**部分实现** = 已有核心数据或操作，但入口、闭环或场景覆盖尚不完整；**占位** = 已有导航/页面，但当前仅显示 Coming soon。

## Requester 端（客户请求与跟进）

| 业务环节 | 当前功能 | 状态 |
| --- | --- | --- |
| 工作台与待办 | 展示请求概览、需要关注的事项及快捷创建入口。 | **已实现** |
| 请求列表 | 查看本人请求及组织共享请求，支持筛选、分页和进入请求详情。组织共享请求为只读。 | **已实现** |
| 新建请求 | 通过三步向导完成来源、配置和报价；可按专利号检索，也可直接上传文件发起（目前只有EP的业务）。 | **已实现** |
| 专利检索与资料选择 | 检索专利、选择候选专利及相关文件，并展示专利书目信息。 | **已实现** |
| 文件解析与 OCR | 对有效专利/上传文件发起解析，展示页数、字数、权利要求和附图等结果；解析未完成时不能生成报价（涉及翻译业务时）。EP Granting 支持 TIFG clean-copy PDF 及 claims-only 解析。 | **已实现** |
| 服务配置 | 选择服务路径、服务项、源/目标语言、紧急程度、翻译范围和目的国/地区；覆盖现有 EP Granting、Traditional Validation、Unitary Patent、Traditional Validation + Unitary Patent。 | **已实现** |
| 草稿 | 保存请求草稿、按条件筛选草稿、恢复后继续填写向导。 | **已实现** |
| 报价预估 | 调用 ERP 获取实时预估报价、切换币种，并导出 PDF 报价单。 | **已实现** |
| 请求跟进 | 查看请求状态、截止日、专利/文件资料与报价。 | **已实现** |
| 签署文件 | 查看并提交签署文件 |  |
| 订单与交付物 | 查看本人Request的金额、交期、确认时间、状态和交付进度；按目的国/地区下载已发布交付物。 | **已实现** |
| 组织与成员 | 组织功能受开关控制；支持成员、邀请及共享请求查看，组织管理员可邀请成员。（后续可能考虑开放，测试阶段） | **部分实现** |

## 两端衔接关系

```text
Requester：提交资料 → 文件解析/OCR → 配置服务 → ERP 预估与提交 → 确认报价或协商
                                                                  ↓
PM：请求池处理 → 制作报价/协商 → 接受报价后启动订单与翻译任务 → 上传并提交交付物
                                                                  ↓
Requester：查看订单进度并下载已发布交付物
```

## 边界说明

- 文件解析、OCR、专利检索和 ERP 预估是 Requester 建请求链路能力；PM 仅在请求详情中查看这些已产生的资料与结果，并不在 PM 端发起解析或 OCR。
- 订单、翻译任务、交付物与事件记录等底层数据模型由两端共享，但页面动作按角色权限区分。
- Translator 的任务数据和权限基础已存在，但本矩阵按范围未列入第三端功能。
